# Go/No-Go Checklist

Run this as a 15-minute call the day before the release window. One person (the release manager or RTE) chairs it and records the decision.

**Release:** ______  **Window:** ______  **Chair:** ______

## Readiness
| # | Question | Yes / No | Notes |
|---|---|---|---|
| 1 | Is CAB approval in place? | | |
| 2 | Is testing complete, with no open critical or high defects? | | |
| 3 | Has the rollback been tested, and does everyone know the trigger for using it? | | |
| 4 | Are dependent teams' changes ready, or confirmed not needed? | | |
| 5 | Is the environment stable, with no conflicting changes in the same window? | | |
| 6 | Are the deployment team, approvers and on-call support confirmed? | | |
| 7 | Is business PVT staffed, with a named tester and a time slot? | | |
| 8 | Have support teams and affected stakeholders been told what's changing? | | |

## Decision
- **Go:** all answers are Yes, or every No has an accepted mitigation recorded below.
- **No-go:** any No without a mitigation. Agree the new date and the owner of each open item before the call ends.

**Mitigations accepted:**

**Decision:** Go / No-go   **Time:** ____   **Recorded by:** ____

> Tip: a no-go is a good outcome when the checklist did its job. Record it without blame and keep the trend in your monthly metrics.
